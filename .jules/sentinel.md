## 2026-07-24 - Role-Based Access Control on resolveUser Middleware
**Vulnerability:** A standard RBAC authorization vulnerability existed where the `/admin` router was protected by a hardcoded user ID check (`Number(req.user.id) === 15`), and other role-dependent code could not securely read the active user's roles because `resolveUser` middleware only selected `id` and `username` from the `users` table.
**Learning:** Hardcoding specific user IDs bypasses standard RBAC patterns, limits scale, and violates security principles such as defense-in-depth and least-privilege tracking. Furthermore, omitting role metadata from the session resolver makes it impossible for downstream routes and action-auditing subsystems to map security privileges accurately.
**Prevention:** Always select full authorization metadata (e.g., `roles`) inside authentication/user-resolution middleware, and enforce authorization policies utilizing structured checks (e.g., array intersection or helper functions) rather than user-identifier values.
