## 2025-06-16 - Prevent PII Exposure on Unauthenticated Public Profile Routes
**Vulnerability:** The public-facing, unauthenticated route `/profile/public/:userId` was selecting and returning the `resume_text` database field. This field contains highly sensitive Personally Identifiable Information (PII) of users, such as phone numbers, physical addresses, previous employment, and contact details, making it accessible to any unauthorized request or web crawler.
**Learning:** Overly permissive query selection (e.g. including every available user profile text field in SQL SELECT queries) during profile data retrieval often leads to unintended exposure of PII on guest-accessible endpoints. Even if the frontend UI initially does not display the field, the raw API response still exposes it.
**Prevention:** Always explicitly define minimal query projection fields on unauthenticated routes, and ensure all PII fields (like `resume_text`, `email`, or other contact fields) are strictly omitted from public selectors unless explicitly authorized or sanitized. Verify field exclusion in comprehensive router unit/integration tests.
