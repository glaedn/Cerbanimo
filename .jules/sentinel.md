## 2026-07-21 - Unauthenticated Public Route Exposing Sensitive Resume PII
**Vulnerability:** The unauthenticated `GET /profile/public/:userId` route returned the complete `users` record including the `resume_text` field, which frequently contains highly sensitive Personally Identifiable Information (PII) like email addresses, phone numbers, and physical addresses.
**Learning:** The database query in `GET /profile/public/:userId` was selecting the `resume_text` column and sending the raw record to the client with `res.json()`. Because there was no token verification middleware on this public-facing endpoint, any client could fetch any user's private resume data simply by querying their user ID.
**Prevention:** Ensure that all unauthenticated endpoints that expose user records explicitly exclude private/sensitive columns (such as `resume_text`, `email`, `password`, `secrets`, etc.) from their SQL queries. Always restrict database selections to the minimum subset of fields needed for public rendering.
