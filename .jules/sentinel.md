## 2025-05-18 - Role-Based Access Control and Privilege Escalation Prevention
**Vulnerability:** A hardcoded user ID value (`Number(req.user.id) === 15`) was used as the sole administrative check in `backend/routes/admin.js` (`isAdmin` middleware). Additionally, the core `resolveUser` middleware only selected `id` and `username` from the `users` database table, omitting user roles entirely.
**Learning:** Hardcoded identifier authorization checks introduce severe maintenance overhead and allow potential privilege escalation if IDs are recycled or reassigned. Moreover, failing to load and attach permission/role collections early in the request lifecycle restricts down-stream authorization checks from utilizing standardized RBAC patterns.
**Prevention:** Always select and bind the `roles` array within the authentication/session resolution middleware (`resolveUser`) so it is universally accessible across routers. Secure administrative or privileged endpoints strictly via dynamic Role-Based Access Control (`req.user.roles.includes('admin')`) rather than hardcoding static user IDs or numeric values.
