## 2026-08-02 - Exposing Sensitive User Resume Text on Public Profiles
**Vulnerability:** The public profile route `GET /profile/public/:userId` was returning the full `users` row, including the `resume_text` field. Since this endpoint has no authentication, any visitor could access a user's resume, leaking private personally identifiable information (PII).
**Learning:** When developing new database columns or fields (like `resume_text` introduced for AI-powered resume analysis), developers often append them to the main `users` table. If preexisting endpoints use overly broad queries (like querying all fields or explicitly adding new fields to an unauthenticated public select statement), new sensitive fields can easily be leaked to the public.
**Prevention:** Always practice data minimization on public, unauthenticated routes. Select only the absolute minimal set of necessary fields (e.g., username, profile picture, public badges) in database queries instead of querying the full user record or including raw document fields like resumes. Always write integration tests verifying that sensitive columns (such as `resume_text`, password hashes, or emails) are strictly absent from public API responses.
