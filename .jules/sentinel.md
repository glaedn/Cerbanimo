## 2026-07-27 - Hardcoded User ID Administration Check and Missing Roles Fetching
**Vulnerability:** The platform's administration router `/admin` used a weak security check that hardcoded user ID 15 (`req.user.id === 15`) to grant administrative access. This bypasses proper Role-Based Access Control (RBAC). Furthermore, the core user resolution middleware `resolveUser` did not retrieve user `roles` from the database, rendering any dynamic role-based access checks (like checking `roles` for `'admin'`) broken or unusable because `req.user.roles` was always undefined.
**Learning:** Hardcoded identifier checks are extremely fragile, error-prone, and violate the principle of least privilege. In this case, standard RBAC structures were partially expected/designed across the codebase but were left unimplemented at the middleware database query level, leading developers to fallback to fragile user ID-based checks.
**Prevention:** Ensure that core user identity and access context (such as roles, permissions, scopes) are fully populated by authentication and database resolution middlewares. Avoid any user ID hardcoding for access control; instead, design and strictly enforce dynamic role/permission-based decorators or middlewares (`isAdmin`, `hasScope`).
